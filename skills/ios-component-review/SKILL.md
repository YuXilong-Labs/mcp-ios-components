# iOS 组件复用审查

## 目标

识别并拦截“可复用却未复用”的改动，防止重复造轮子进入主干。

## 审查清单

### A. 复用性检查

- 是否新增了已有能力的平行封装
- 是否绕过了基础组件直接使用底层实现
- 是否有可替换成现有组件 API 的代码

### B. 证据检查

对疑似重复点，必须给出：

1. `search_component` 命中证据
2. 对应 `get_component_api` 片段
3. 建议替换 API

### C. 风险检查

- 兼容性（参数/返回）
- 错误处理一致性
- 日志/埋点/监控是否丢失

## 输出格式

### 审查结论
- 通过 / 需整改 / 阻塞

### 问题项
- 文件位置
- 问题描述
- 可复用组件证据
- 修复建议
- 严重等级（高/中/低）

### 建议动作
- 必改项
- 可延后项

## 参考资料

- 严重级别判定：`references/severity-rubric.md`

## 阻塞规则（默认）

命中以下任意情况可标记阻塞：

- 新增基础能力重复实现且已有稳定组件
- 绕过统一网络/路由/图片基础设施
- 替换建议明确但无合理豁免说明
