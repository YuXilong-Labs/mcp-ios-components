# iOS 重复实现迁移到基础组件

## 目标

对已有业务代码做“识别 -> 映射 -> 替换 -> 验证”的迁移流程，避免大爆改。

## 迁移流程

### Step 1: 识别重复实现

查找典型信号：

- 自定义 URLSession 请求封装
- 手写图片下载/缓存
- 直接控制器跳转而非 Router
- 自定义弹窗/Toast 与基础 UI 库重叠

### Step 2: 建立映射

通过 `search_component` + `get_component_api` 建立：

- 旧实现能力 -> 目标组件
- 旧调用点 -> 新 API
- 兼容性风险（参数、返回值、线程、错误处理）

### Step 3: 分批替换

按最小风险顺序改造：

1. 新增适配层（必要时）
2. 替换单个场景
3. 小范围验证
4. 扩展替换

### Step 4: 验证与回滚策略

输出：

- 已替换清单
- 未替换原因
- 风险点
- 快速回滚路径

## 输出格式

1. 重复实现识别结果
2. 迁移映射表
3. 代码改动建议（按批次）
4. 验证计划

## 规则

- 不允许“一次性全量替换”无验证
- 不允许替换后功能语义变化但未说明
- 不允许引入新的平行基础层
